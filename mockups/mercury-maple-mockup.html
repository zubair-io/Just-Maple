Launch Strategy Q2

Launch Strategy: Mercury Maple

The core proposition is intent-driven navigation — replacing the traditional sidebar-and-page model with a fluid, contextual workspace that assembles around what you're trying to do.

Technology should serve people, not the other way around. Mercury re-imagines the operating system as a fluid experience driven by human intent.

Key differentiators: the [[Flow Layout]] allows horizontal module composition, so users can work across a memo, chat thread, and todo list simultaneously without context switching. This maps to our [[CRDT Architecture]] — every module is already a Y.js document.

Module Navigation

Modules in a Space are accessed one at a time through the dock. Use ⌘ ↑↓ to move between modules or click the dock icons. The focused module expands while others collapse — maintaining context without visual overload.

  • Each module can link to others via [[wikilinks]], creating a network
  • The connection graph on the right shows how the current module relates to its neighbors
  • Backlinks surface automatically — know what references you without searching
  • Link strength indicates how deeply connected two modules are

Locus as Intent Router

The [[Locus]] command bar becomes the primary entry point — surfacing content by intent rather than hierarchy. Type what you're looking for: "todos due today", "messages from Sarah", "notes about architecture". The system assembles the right module.

Combined with [[Full-text Search]] and backlinks, this creates a knowledge graph navigable through language. The [[Sprint Tasks]] module connects here because launch planning drives task prioritization.
